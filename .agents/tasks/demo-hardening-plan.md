# Demo Hardening Implementation Plan — Well-Architected (demo scope)

Scope: four focused remediations for the SHORT-LIVED DEMO deployment of CraveQuest —
SEC-2 (throttling only), SEC-5/SEC-7 (Secrets Manager for the two tokens), CO-3
(scheduled scale-to-zero off-hours), and PERF-2 (right-size the Fargate task). Every
change is additive, reversible, and either cost-protective or cost-reducing. No
production always-on expense is introduced (no second task, no HTTPS/ACM, no VPC
endpoints, no WAF/authorizer). Teardown stays clean (`cdk destroy`). Work directly on
branch `main`, no worktree.

INFRA is AWS CDK v2 TypeScript (`aws-cdk-lib ^2.147.0`, `constructs ^10.3.0`). Edit ONLY
the `.ts` sources under `infra/` (`bin/`, `lib/`). The compiled `lib/*.js`, `lib/*.d.ts`,
and `bin/*.js` are generated by `tsc` — never edit them. Backend needs NO change for
these four items.

## Grounding notes (verified by reading the code)

- `infra/lib/config.ts` builds `StackConfig` entirely from
  `fromContextOrEnv(app, contextKey, envKey, fallback)` and returns the object from
  `loadStackConfig(app)`. New keys must follow this exact pattern (interface field +
  populated entry in the returned object). Numeric keys are parsed with
  `parseInt(fromContextOrEnv(...,'<default>')!, 10)`; a float uses `parseFloat`. Current
  task sizing defaults are **`cpu: 2048`** (`cpu`/`TASK_CPU`) and
  **`memoryLimitMiB: 8192`** (`memoryLimitMiB`/`TASK_MEMORY_MIB`). `desiredCount` default
  is `1` (`desiredCount`/`DESIRED_COUNT`).
- `infra/lib/cravequest-stack.ts` already imports `cdk`, `ec2`, `ecs`, `ecr_assets`,
  `elbv2`, `iam`, `logs`, `apigwv2`, `apigwv2_integrations`, `amplify`, `cloudwatch`,
  `cloudwatch_actions`, `sns`, `sns_subscriptions`, `budgets`, `path`, and `StackConfig`.
  It does NOT yet import `secretsmanager` or `applicationautoscaling` — both must be
  added.
- The HTTP API is `const httpApi = new apigwv2.HttpApi(this, 'BackendApi', {...})`. The
  L2 `HttpApi` auto-creates a `$default` stage reachable via `httpApi.defaultStage`
  (type `IHttpStage`; concrete `HttpStage`). There is **no** throttle prop on `HttpApi`
  or in `addRoutes`. Throttling must be set on the default stage's underlying
  `CfnStage.defaultRouteSettings` (`throttlingRateLimit` / `throttlingBurstLimit`) via
  the escape hatch `httpApi.defaultStage.node.defaultChild as apigwv2.CfnStage`.
- The Fargate service is `const service = new ecs.FargateService(this, 'BackendService',
  { ..., desiredCount: config.desiredCount, ... })`. `service.autoScaleTaskCount(...)`
  returns an `applicationautoscaling.ScalableTaskCount` exposing `scaleOnSchedule(id,
  { schedule, minCapacity?, maxCapacity? })`. `applicationautoscaling.Schedule.cron(...)`
  builds the cron. The container is `const container = taskDefinition.addContainer(
  'Backend', { image, logging, environment: {...}, portMappings, healthCheck })`.
- The container `environment` map today sets `DECIDER_MODE`, `DECIDER_MODEL`,
  `STRANDS_DECIDER_API_BASE`, `DECISION_TIMEOUT_MS`, `DECISION_CONFIDENCE_THRESHOLD`,
  Bedrock vars, `AWS_REGION`, and `ALLOWED_ORIGINS`. It does **NOT** set
  `STRANDS_DECIDER_API_KEY` or `METRICS_ACCESS_TOKEN` as plaintext — so there is **no
  plaintext token wiring to remove**. `addContainer` currently passes no `secrets:` map;
  the `secrets:` key must be added.
- Backend env var names are confirmed exact in `backend/app/config.py`:
  `STRANDS_DECIDER_API_KEY` (alias of `strands_decider_api_key`, optional, default None)
  and `METRICS_ACCESS_TOKEN` (alias of `metrics_access_token`, optional, default None).
  Both are optional — empty secrets are fine until the operator populates them; the app
  treats an unset Decider key as "no bearer token" and an unset metrics token as "metrics
  endpoint not publicly exposed". No backend code change is needed; the ECS `secrets:`
  path injects the SAME env var names, just sourced from Secrets Manager instead of plain
  env.
- `taskRole` is `const taskRole = new iam.Role(this, 'BackendTaskRole', {...})`. Grant
  scoped read with `secret.grantRead(taskRole)` — do NOT widen to `*`. (The execution
  role also needs read access to decrypt/fetch the secret at task launch; `ecs.Secret`
  wiring grants the execution role automatically, so no manual execution-role grant is
  required. See item 3 note.)
- Build/synth: `cdk.json` app is `npx ts-node --prefer-ts-exts bin/cravequest.ts`. Fast
  gate is `npm run build` (tsc, from `infra/`). `npx cdk synth` renders the template but
  BUILDS THE DOCKER ASSET (needs Docker running) and is slower; use it to confirm
  synthesized values. There are no infra jest tests today (`npm test` runs jest but no
  specs exist) — verification is tsc + synth-output inspection, matching the project's
  current reality and Bucket A's approach.
- No `AGENTS.md`, `CONTRIBUTING`, or `.kiro/steering/*` exist; conventions are inferred
  from the existing code (typed CDK L2 constructs; config via `fromContextOrEnv`; README
  config table kept in sync).

## Design decisions recorded (made here, grounded in the code)

- **SEC-2 — set throttling on the default stage via escape hatch.** The L2 `HttpApi`
  exposes no throttle prop, and `apigwv2` has no higher-level per-stage throttle setter.
  Decision: reach `httpApi.defaultStage.node.defaultChild as apigwv2.CfnStage` and set
  `defaultRouteSettings = { throttlingRateLimit: config.apiThrottleRateLimit,
  throttlingBurstLimit: config.apiThrottleBurstLimit }`. This is the idiomatic escape
  hatch for the default `$default` stage and keeps the demo-sane caps (20 req/s, burst 40)
  so a spike can't fan out into paid Bedrock calls. No authorizer/WAF/CloudFront (out of
  scope).
- **SEC-5/SEC-7 — two separate empty secrets, created in-stack by default.** Decision:
  create two `secretsmanager.Secret` constructs (one per token) with NO
  `generateSecretString` producing a usable value and NO hardcoded value — each is an
  empty placeholder the operator populates post-deploy with `aws secretsmanager
  put-secret-value`. Two secrets (not one JSON secret) keeps each `ecs.Secret.
  fromSecretsManager(secret)` wiring simple (no `field` arg) and lets the operator rotate
  them independently; it also matches the two distinct backend env vars cleanly. Synth
  works out of the box (empty secrets are valid). `secret.grantRead(taskRole)` scopes read
  to exactly these two secret ARNs.
- **SEC-5/SEC-7 — optional ARN/name override via config.** Decision: add optional config
  keys so an operator can REFERENCE a pre-existing secret by ARN instead of creating one
  (useful if secrets are managed centrally). When the override is set, use
  `secretsmanager.Secret.fromSecretCompleteArn(this, id, arn)`; otherwise create a new
  empty secret. This keeps the default (create empty) zero-config while allowing the
  cleaner reference path without code edits.
- **CO-3 — scale-to-zero via a scheduled Application Auto Scaling action only.** Decision:
  `service.autoScaleTaskCount({ minCapacity: 0, maxCapacity: 1 })` then two
  `scaleOnSchedule` actions — DOWN to `minCapacity: 0, maxCapacity: 0` at 20:00 and UP to
  `minCapacity: 1, maxCapacity: 1` at 08:00. This introduces `autoScaleTaskCount` with
  `minCapacity: 0` for the demo scale-to-zero schedule ONLY. NO CPU/request target-tracking
  autoscaling and NO `desiredCount >= 2` (Bucket C, out of scope). Steady state outside the
  down-window is a single task (capacity 1), matching the current `desiredCount: 1`.
  Gated behind `enableScheduledScaling` (default `true`) so it can be turned off with one
  flag.
- **CO-3 — cron semantics.** Decision: schedules use `applicationautoscaling.Schedule.
  cron({...})` parsed from two configurable cron expression strings. Application Auto
  Scaling cron is UTC and uses the AWS 6-field `cron(Minutes Hours Day-of-month Month
  Day-of-week Year)` form; the config stores the inner fields. Defaults: DOWN `0 20 * * ? *`
  (20:00 UTC daily), UP `0 8 * * ? *` (08:00 UTC daily). Documented as UTC in the README so
  the operator can adjust for their timezone.
- **CO-3 — desiredCount interaction.** Decision: keep `desiredCount: config.desiredCount`
  (1) on the service. Once `autoScaleTaskCount` registers a scalable target, Application
  Auto Scaling owns the running count; the UP schedule restores it to 1 and the DOWN
  schedule drops it to 0. We do not change `desiredCount`. This is called out so the
  implementer does not also try to zero `desiredCount`.
- **PERF-2 — right-size defaults in config.ts only.** Decision: change the `cpu` default
  `2048 -> 512` and `memoryLimitMiB` default `8192 -> 1024` (a valid Fargate combo: 0.5
  vCPU / 1 GB). Keep them as configurable `fromContextOrEnv` defaults (do NOT hardcode in
  the stack). Add a brief comment noting the task currently runs only FastAPI (no
  co-located 2B model in the Dockerfile), so the generous sizing was unnecessary for the
  demo; if the Decider is later co-located, sizing should be revisited (note only — do not
  implement provisioning/GPU, Bucket C).

## Notes / assumptions

- No infra jest tests exist; verification relies on `tsc` + `cdk synth` output inspection,
  the project's current reality (consistent with Bucket A). Adding a first jest synth test
  is optional and out of scope for this demo pass.
- `npx cdk synth` builds the Docker image asset and therefore requires Docker to be
  running and may be slow; if Docker is unavailable in the implementer's environment, the
  `npm run build` tsc gate still validates all TypeScript and construct wiring, and the
  synth-value confirmations should be run wherever Docker is available before deploy.
- App Auto Scaling cron is UTC and uses the 6-field `cron(min hour day-of-month month
  day-of-week year)` form; defaults encode 20:00/08:00 UTC. The operator adjusts the cron
  config keys for their timezone (documented in the README).
- Two separate secrets (vs one JSON secret) were chosen for simpler per-token
  `ecs.Secret.fromSecretsManager` wiring and independent rotation; if the operator prefers
  one JSON secret they can create it and pass both ARNs via the override keys (the field
  form would then differ — out of scope for the default path).
- `below`-scope reminder: backend requires NO change — the ECS `secrets:` path injects the
  same `STRANDS_DECIDER_API_KEY` / `METRICS_ACCESS_TOKEN` env var names the backend already
  reads; both are optional in `config.py`, so empty secrets keep synth and startup valid
  until populated.
