# Bucket A Implementation Plan — AWS Well-Architected (safe, additive, low-risk)

Scope: the 9 Bucket A remediations from `.agents/tasks/well-architected-review.md` section 8.A. Every item is additive and reversible with no change to user-facing behavior. INFRA is AWS CDK v2 TypeScript (`aws-cdk-lib ^2.147.0`); BACKEND is Python 3.11 stdlib-only for the new code (FastAPI app, no new third-party deps). Deployment-specific values become `config.ts` keys read from CDK context/env with safe defaults, following the existing `fromContextOrEnv` pattern.

## Grounding notes (verified by reading the code)

- `infra/lib/config.ts` builds `StackConfig` entirely from `fromContextOrEnv(app, contextKey, envKey, fallback)`. New keys must follow this exact pattern. There is no `environment` field today; `allowedOrigins` defaults to `http://localhost:5173`.
- `infra/lib/cravequest-stack.ts` already imports `cdk`, `ec2`, `ecs`, `ecr_assets`, `elbv2`, `iam`, `logs`, `apigwv2`, `apigwv2_integrations`, `amplify`, `path`. It does NOT yet import `cloudwatch`, `cloudwatch_actions`, `sns`, `sns_subscriptions`, or `budgets`. The service is `new ecs.FargateService(this, 'BackendService', ...)` (var `service`); target group comes from `listener.addTargets('BackendTargets', ...)` (the return value is not currently captured); container listens on `8080`; `this.region` is available.
- `infra/bin/cravequest.ts` sets stack-level tags only via the `tags:` StackProps (`Project`, `ManagedBy`). It does not call `cdk.Tags.of(...)`.
- Backend has NO logger configured anywhere. `main.py`'s `unhandled_exception_handler` does `del request, exc` and logs nothing. `recipes.py` calls `run_request(...)` with no `request_id` (the orchestrator generates a UUID internally and returns it as `GenerateResponse.request_id`, but it is not logged and not read from an inbound header).
- `orchestrator.run_request` calls `_resolve_adapter(resolved_settings)` per request, which calls `RealDeciderAdapter.from_settings(...)` (cheap) — the Decider adapter uses litellm, not boto3. The boto3 client is built inside `BedrockGenerator._get_client()`. The generator is constructed inside the strategy tools (`quick_recipe`/`leftover_remix`/`no_cook_snack` in `app/tools/`), each of which calls `BedrockGenerator.from_settings(...)` per request — so the boto3 `bedrock-runtime` client is rebuilt per request. PERF-3 must cache the client without altering retry/backoff/timeout logic.
- `metrics_collector.py` exposes `MetricsCollector.fallback_rate()` and a process-wide singleton via `get_metrics_collector()`.
- `backend/app/api/health.py` serves `GET /health` returning `{status, timestamp}` only. The container `EXPOSE 8080`; Dockerfile has no `HEALTHCHECK`. `python:3.11-slim` has python3 but not guaranteed curl.
- Build/test commands: INFRA — `npm run build` (tsc) and `cdk synth` (via `npx ts-node` app, configured in `cdk.json`), `npm test` (jest, but no infra tests exist yet). BACKEND — `pytest` (dev deps: `pip install -r requirements-dev.txt`), tests in `backend/tests/`.
- Compiled output (`lib/*.js`, `lib/*.d.ts`, `bin/*.js`) is generated by `tsc`; edit only the `.ts` sources.

## Design decisions recorded (made here, grounded in the code)

- CO-1/OE-1 share ONE SNS topic `OpsAlerts`. Decision: a single topic keeps subscriptions and billing simple and matches the task guidance to reuse it.
- Billing `EstimatedCharges` CloudWatch alarm is NOT created (it only exists in `us-east-1` and would break synth in other regions). Decision: rely on the AWS Budgets notification path; add a commented, region-gated stub so intent is documented without risking synth.
- SEC-4: keep the existing `DockerImageAsset` flow (switching to an explicit `ecr.Repository` + manual push is brittle and risks breaking the asset pipeline). Decision: document account-level Amazon Inspector for ECR via a code comment + README note. Least-disruptive, synth-clean.
- REL-2 observability: emit the fallback rate as CloudWatch EMF JSON to stdout (no extra IAM, CloudWatch extracts it from logs). Decision: EMF over `PutMetricData` to avoid widening the task role.
- OE-3 health check: use a Python one-liner (`python -c "import urllib.request,sys; ..."`) rather than installing curl, avoiding an extra apt layer on `python:3.11-slim`.
- Config defaults: `budgetMonthlyLimitUsd` default `50`, `environment` default `dev`, `owner` default `unknown`, `fallbackRateAlarmThreshold` default `0.5`, `opsAlertEmail`/`budgetNotificationEmail` default unset (empty). All via `fromContextOrEnv`.
